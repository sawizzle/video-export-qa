# Running the video-export-qa tests

Run from the repository root:

```powershell
python -I -B -m unittest discover -s 'tests/video-export-qa'
```

The suite needs ffmpeg and ffprobe on PATH (ffmpeg 4.4 or newer). To compare builds, put the other ffmpeg directory first on PATH and keep the rest of PATH. The suite has 985 tests.

## Portable fixtures

All fixture compatibility lives in [ffmpeg_fixtures.py](ffmpeg_fixtures.py). The [product scripts](../../packages/video-export-qa/scripts/) are always run unchanged: the tests adapt only the commands that build test clips and reference output.

- Real one-frame probes cache whether a build accepts `-fps_mode` or `-display_rotation`, once per executable. Fixture and reference commands use `-fps_mode` when it exists and otherwise the exact older spelling: passthrough = `-vsync 0`, vfr = `-vsync 2`, cfr = `-vsync 1`.
- A few tests skip and say why: `test_compare.py` and `test_gif.py` as a whole when ffmpeg or ffprobe is not on PATH (reason `ffmpeg and ffprobe are required on PATH`), the rotation tests when the build lacks `-display_rotation` (reason `ffmpeg build lacks -display_rotation`), the ProRes 10-bit barcode test when the build has no prores_ks encoder (reason `this ffmpeg build has no prores_ks encoder`), the link test of `test_v11_regressions.py` when the system can make neither a symbolic link nor a junction to a folder (reason `this system cannot make a link or junction to a folder`), the deleted-current-folder test on Windows, the two private-term scans where their local deny-list file is absent, the forced-colour test on a build that ignores `AV_LOG_FORCE_COLOR`, the full-range conversion test on a build whose ffprobe names full-range 4:2:0 `yuv420p` instead of `yuvj420p` (reason `this ffprobe build does not name full-range 4:2:0 yuvj420p`), the raw HEVC and raw AV1 fixtures when the build has no libx265 or libsvtav1 encoder (the tests that need them skip, with the reason), the VP9/AV1 full-range-name test when the build has neither libvpx-vp9 nor libsvtav1, and everything that reads the listing source when the `listing` folder is not part of the checkout (the public repository has only `packages/` and `tests/`; reason `the listing source folder (listing/) is not part of this checkout; the public repository has only packages/ and tests/`): nine whole tests, plus the listing part of three others, whose package part still runs. The two route modules have skips of their own (listed below). Apart from the skips named here and below, a failure to build a fixture, or an unexpected probe error, is an assertion failure in the tests that use it, not a skip.
- The probe fixtures use a test picture (not a flat colour) for the odd-size clips and check the stored width and height with ffprobe. The clip that starts 2 s in is made by remuxing an encoded clip and is checked with ffprobe.
- The frame and integration fixtures that are meant to be constant frame rate say so (`-fps_mode cfr -r 24`). The variable frame rate fixtures keep their timestamps. The GIF fixtures give the last 30 fps frame an explicit delay instead of inheriting one that depends on the ffmpeg version.
- The Windows-only `?` folder-name case runs only on Windows. The "path below a regular file" case runs everywhere.
- The audio tests check that a readable generated clip actually reached measurement before they use any number from it, so a product filter failure fails there instead of surfacing later as arithmetic on `None`.
- `test_v12_docs.py` checks that the documents say what the code does: every command in the docs starts at `<skill-dir>/scripts/`, run_qa.py's flags are not confused with qa_frames.py's, the always-on checks, the Limits and the spec-key table are written down, the test counts in the docs are the real count, and the listing source has no stale claim. Its negative controls show each scanner can fail. It also runs the commands and values the guidance tells a reader to use (the colour-tagging recipe, the range conversion, the barcode region formula, the barcode-run example spec, the HDR colour strings) on clips it makes itself, so a documented recipe that stops working fails here. In this module and in `test_v12_regressions.py`, numbers that depend on the ffmpeg build are accepted when they are one of the values the documents give (the documents name the builds each value was measured on; the tests do not check which build produced which value), not only the value of one build: the true peak of the AAC tone (-19.7 or -20.0 dBTP), what a plain `-pix_fmt yuv420p` does to a full-range source (the file stays `yuvj420p` with range `pc`, or becomes `yuv420p` with range `tv`), and the average frame rate ffprobe prints for the raw MPEG-4 fixture (`25/1` or `0/0`, never the clip's own `24/1`).
- `test_v12_regressions.py` covers the version 1.2 changes. It makes its clips in the system temporary folder and removes them afterwards. Its raw streams (H.264 always; MPEG-4, MPEG-2 and MJPEG with ffmpeg's own encoders; HEVC and AV1 when the build has libx265 and libsvtav1), its Matroska file written to a pipe, its APNG and PNG are real ffmpeg output (no timestamps or no recorded length); the same codecs in MPEG-TS and AVI, and an Apple-style .m4v (an MP4 container), are the controls that must stay measured. One fixture is a stand-in ffprobe that runs the real one and leaves `nb_frames` out of the stream list, to test GIF handling on builds that do not report a frame total; it is not a different ffprobe version.

- `test_v121_no_skill_folder.py` covers the route for an agent that has the skill only as text, added in 1.2.1 and rebuilt in 1.2.2. Both releases changed documents, tests and the version number only (no script behaviour changed). It checks that the file sets in `references/no-skill-folder.md` are exactly what the scripts import and open (a walk of their syntax trees), copies each set alone into an otherwise empty folder and runs it on clips made here (help, a real run, and a negative control: leaving out any one file of a set makes it fail), takes the program out of that document verbatim and makes every set through it from simulated answers (saved as plain text, saved as JSON, written by hand from a result shown in the conversation, and one older-shape answer), runs the scripts from that folder, runs the commands of the document as written in bash and Windows PowerShell, and pins the new text in `SKILL.md`, `README.md` and the reference (among it every size of the document's section 1 against the real files in KB of 1,000 bytes, what each size difference of a refused hand copy means, 0 and the escape slips included, which scripts hold backslashes, and the rule of section 7 for a Windows temp folder outside the user folder). These route tests assume a temp folder whose path is plain ASCII: run them with TEMP, TMP or TMPDIR set to such a folder. Its negative controls: a wrong hash, a missing file, a planted module (shown to run when the check is skipped), a foreign layout, an existing folder handed to the program, and hand copies with the usual slips (and `put` into the folder that still holds the refused copy).
- `test_v122_extractor.py` (1.2.2) attacks the program of that document the way the shared design was attacked: the program and its table are the generator's output for the real files, and the template and the generator under `route2/` are the audited ones (pinned by SHA-256; the program differs from the template only in the filled-in names and table and in its first-line comment, which `_route2.py` replaces because the template's overstated what a copy cut short does); fresh folders only, no argument to `new`; folders that are not fresh, planted modules, links, junctions, loose modes and a race on the exclusive create; names and the escaping of untrusted text and of paths that hold a control character, and the document's folder name and accented-path example against what the program really prints; a temp folder owned by another user, even at mode 1777 (two-user tests); every saved shape and hostile saved files with a memory bound; a quoted bash heredoc, the whole program inside the Bash-tool command limit, copies cut short anywhere, and PowerShell here-strings. `_route2.py` holds the generator of the document's program and table (`python -I -B tests/video-export-qa/_route2.py program`) and the runner the tests share.
- `get_skill_sim.py` simulates a tool that gives a skill as text, for any package folder: `python -I tests/video-export-qa/get_skill_sim.py packages/video-export-qa sim_out` writes into the new folder `sim_out` the first answer (listing text, `SKILL.md` inline, an index of files with sizes), the result for each file in three forms (as shown, saved as plain text, saved as JSON), the older answer with every file as a `### File:` block, and `fake_get_skill.py`, a stand-in for the tool with the package inside it. In `sim_out`, `python fake_get_skill.py` prints the first answer and `python fake_get_skill.py --file video-export-qa/scripts/qa_probe.py` the result for one file; a result over 30,000 characters (`--inline-limit` changes that) is saved under `sim_out/tool-results/` (JSON over 50,000 characters, plain text otherwise) and only a short message with its path is printed, as a host does. Its JSON form of `scripts/qa_probe.py` is byte for byte the file a real host saved on 2026-10-15.
- Skips in these two modules, each with its reason: the tests that run a script on a clip need ffmpeg (`ffmpeg and ffprobe are required on PATH`); the bash tests need `sh`; the PowerShell tests run only on Windows, and so does the junction test; the mode, temp-folder and memory-limit tests run only on POSIX, and so does the test of a temp folder whose name holds a control character (`file names with control characters are POSIX only`); the link test needs an account that can make symbolic links; the two-user tests run only as root on Linux with `VEQA_TWO_USERS=victim:attacker` (two accounts in a throwaway container); the real-answer test runs only when `VEQA_REAL_ANSWERS` names answers a real host saved (they are in no checkout); the listing part skips when `listing/` is absent.

- Every module that makes clips works in a folder of its own: `_work/video-export-qa/<group>/<name>-<process id>-<random>` (`private_work_folder` in `ffmpeg_fixtures.py`, removed when the run ends) or a fresh folder from `tempfile`. Earlier versions used fixed folder names, and two runs that overlapped (a second terminal, a review running while another run was going) overwrote each other's clips ("moov atom not found"). `test_v12_regressions.py` checks that no module goes back to a fixed folder name. What was observed: one full run on Python 3.14 and one on Python 3.9, started at the same moment from the same checkout, both passed. That is one observation, not a proof that two runs never interfere, so run one suite at a time when you can.

## Rules for editing the tests

Keep every negative control. Use subtests or an outside harness to exercise helper branches without changing the test count. An unexpected encoding error is a failure, not evidence that a capability is missing.
